# ドキュメント作成規約

## スコープ

本規約は、リポジトリ内のすべての `*.md` の**置き場所と記述内容**を定義する。

以下は定義しない。

* ADR(設計判断の記録)。却下した代替案を残すことが ADR の目的であり、本規約の原則と両立しない

## 置き場所

* 決定論的に判定できる制約は、文章ではなく型・スキーマ・lint・テスト・CI・hooks で表現する。文章の規約は機械検証できず、遵守がセッションごとに揺れるためである
* 文章で残すのは機械判定できない事項(設計意図、判断基準)に限る。置き場所はカテゴリ単位で切り、常時ロードされる範囲を最小にする
  * 特定の作業のときだけ必要 → `.claude/skills/<name>/SKILL.md`
  * 特定のファイル群を触るときだけ必要 → `paths` フロントマター付きの `.claude/rules/`
  * どちらにも絞れない → `CLAUDE.md`。「どのセッションでも、これを知らなければ間違えるか」で判定し、挙げられなければ上の2つへ絞り直す。`paths` なしの `.claude/rules/` は CLAUDE.md と同じく常時ロードされるため、置き場所として使わない

## 原則

ドキュメントは、**最終的な設計を最初からそう計画していたものとして記述する**。想定読者は検討の経緯を一切知らない新規参画者とし、経緯を知らなければ意味が通じない文を残さない。

更新は差分の追記ではなく、その時点の最終形への全面的な書き直しとする。

## 書かないもの

* 変更履歴・経緯(「〜を追加した」「当初は〜だったが」「〜から変更」)
* 検討過程(「〜も検討したが見送った」「議論の結果」)
* 会話・会議・レビューへの参照(「前回の指摘により」「相談の結果」)
* 課題管理ツールのID参照(タスクID、チケット番号)
* 未確定であることの但し書き(「暫定」「後で決める」)。未確定なら、確定させるか、その項目自体を書かない

## 理由

**理由は原則として書かない。** 書くのは決定された仕様そのものであり、規定は理由の説明なしに成立していなければならない。

例外は、理由を落とすと読み手が規定を誤って適用するか、不要と判断して壊すときに限る。「理由がなければ読み手は何を間違えるか」を1つ挙げられるかで判断し、挙げられなければ書かない。迷った場合は書かない。

書くときも、同じ理由を項目ごとに繰り返さない。節の全体に効く理由は、節の末尾に1つ置く。

時系列に依存する記述(「当初は」「議論の結果」「却下された」)は経緯であり、例外にあたらない。

## 構造

* 各ドキュメントは冒頭にスコープ(何を定義し、何を定義しないか)を明記する
* スコープ外の項目は、それを担うものとあわせて挙げる。担い手が他のドキュメントのときは、担い手を書かず項目だけを挙げる
* ドキュメント同士の関係(上位・下位、どの文書が何を定めるか)を各ドキュメントに書かない。索引は `CLAUDE.md` が持つ
* 他のドキュメントの規約へ読み手を誘導しない。読むべき規約は `paths` による配置が決める。誘導のみを担う `paths` 付きのファイルは例外とする
* 規定の根拠となる上位の要件は、理由の一部として出典を示してよい

関係の記述を各ドキュメントに置かないのは、ドキュメントを追加・改名するたびに他のすべての冒頭を直すことになるためである。
